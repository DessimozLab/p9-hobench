# LESSONS — process rules for running this project efficiently
(one line per rule, with evidence; pruned at each milestone)

- Prepend conda_envs/ortho/bin to PATH and use absolute paths for nextflow/FastOMA; plan for ~50 GB cgroup RAM (not 503 GB), omamer parallelism <=2, tool work dirs on local NVMe /tmp. Evidence: M0 first FastOMA attempt failed in 1 s; 4 parallel omamer killed; scratch I/O 31 min sys vs 22 user.
- Never let demo/test scripts write into shared data dirs. Evidence: toolkit demo wiped 109 downloaded proteomes (M1).
- Cap concurrent agents at <=4-5, use Sonnet for bulk parsing, resume rather than relaunch, and assume outages: checkpoint to git/disk and keep a restart queue. Evidence: 13 agents died at T+1h05 (~3.8 h lost); outages 2 (~20:20-23:10) and 3 (~02:55-07:15, killed SwissTree extension and evaluator) each cost hours.
- Ranked work so droppable items are last; cut scope when an outage hits and freeze when launched work finishes. Evidence: D8 cut six items, M4 froze at T+10h30 vs T+12 target, SwissTree dropped after outage 3 with no harm to REPORT.
- Run negative/trivial controls (all-singletons, flat, one-big-HOG, random relabel) on real data BEFORE trusting a metric and gate every scoring run on them. Evidence: controls exposed E1 (singletons 0.86 event recovery), E2 (flat projection bug), E4 (one-big-HOG "recovers" leaf events), E5 (U-root membership; all-singletons 1.000 on K); none was found by the metric's author.
- Treat every metric fix as a logged erratum with before/after tables and re-run all panels; decide it before looking at method rankings. Evidence: ERRATA E1-E5 moved OF event recovery 0.122->0.060 and FastOMA 0.306->0.134; E4 fixed before E/P/V scored.
- Pre-register thresholds and mark post-hoc additions as such; do not relax rules to rescue coverage. Evidence: 80% mapping rule kept (E06, P01 non-headline); balanced merge accuracy flagged POST-RESULTS (E3).
- Do not conclude from underpowered tests: report n and the minimum attainable p. Evidence: Y+K confirmatory n=2 gives min p=0.5, all Holm p=1.0; only the 5-panel n=13 test reached p=0.035.
- Get independent review before scaling AND an independent claim check before release; do not self-certify. Evidence: round 1 (7 reviewers) found interval-reference and beta-lactamase defects; claim check REPORT_CLAIM_CHECK.md forced corrections to REPORT (3d57541b); round 2 added the controls track.
- Make provenance mechanical: parsers, verified quotes, blind re-derivation, hash freeze, early denylist audit for tool-derived "literature" tables. Evidence: blind verification 21/22; Braasch 2016 ohnologs came from Ensembl Compara (V05 cancelled); audit found 0 violations.
- Abandon a family fast with a logged reason when <4 panel species have IDs. Evidence: K03, E09, E10, P06, Y04 abandoned cheaply; E06/P01 stayed non-headline.
- Ask humans for data early and check requested/ every milestone (scripts/check_requested.sh). Evidence: ~90% fulfilled in 1.5 h but unchecked until T+10h; 45/50 delivered.
- Validate cheap subsets against full runs (equivalence test) and add robustness perturbations with a replicate noise floor. Evidence: Y/K subset~=full via TOST +-0.05; OF replicate gave noise floor; taxrm pruning bug found only when perturbations were scored.
- Rerun the whole evaluation after any code fix instead of patching tables, and keep scoring options (--name, subset/full modes) explicit. Evidence: V07 coverage and unit-sharing erratum, taxrm bug, E5 each needed full re-runs and were done cleanly via evaluate_panel.py.
